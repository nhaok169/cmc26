## 2. 核心数学模型：**环抱证书（Encircle Certificate）**

这是本轮最大的方法论创新，它把"全向 + 定向"两类源的**判空问题统一**成一个几何充要条件。

**定义**：对频道 ch，记其**探针集合** `P = {p : 在 p 点停过且测过 ch}`（不仅是有信号的测点，**无信号的测点同样是"该点背对该源的证据"**，信息复用）。

**判据**：频道 ch 必为空 ⟺ 对目标圆域内**任意** G，

```
max_{G ∈ disk(1800)}  maxgap( P ∩ B(G, 1000) )  ≤  180°
```

其中 `maxgap` 是探针相对于 G 的方位角排序后的最大相邻夹角（含首尾环绕）。

**为什么充分**：
- 若 `maxgap(P∩B(G,1000)) ≤ 180°`，则 `G ∈ conv(P∩B(G,1000))`（离散点环抱）。
- 定向源的有效区是**闭半平面**（±90° 含边界）。任意闭半平面必与一个 maxgap≤180° 的点集相交非空。
- 因此无论定向方向 φ 如何，**必有探针落在 G 的点亮半平面内** ⇒ 该源必被检出（或 G 本就无源）。
- 全向源 (360°) 是特例，自然包含。

**为什么必要**：若存在 G 使 maxgap > 180°，则取定向方向背对该最大空隙，全部探针都在盲侧 ⇒ 可能漏检。

> ⚠️ **关键退化情形**：扇区是**闭**的，所以 `maxgap == 180°` 仍然**成立**（不是违规）。
> `ledger2.CERT_MARGIN` 必须为 `-1e-6`（阈值 = 180 + 1e-6），**设成正的 2.0 会把唯一可行的点集误判为不可行**。

## 3. 算法架构：三段式"合并巡回"

```
initial(119s)  →  merged_walk(~7000s)  →  finalize(~460s)
```

1. **`initial_scan`**：在原点把 20 个频道全测一遍（20×5 + 19×1 = **119s** 固定成本）。
   原点对全向源可给出 1 条示向度 ⇒ 为 Q2 的"第二测点推进"提供起点。

2. **`merged_walk`（核心）**：把**证书扫描 + 源定位 + 顺路清除**融进**同一条巡回**，动态重规划。
   - 节点集合 = `待访问证书骨架点` ∪ `已检出未清除源的 MEC 中心`（后者带冷却 `SRC_COOLDOWN`）。
   - 每步：若节点签名变化 ⇒ 用**开放路径 TSP**（`_tsp_open`：最近邻 + 2-opt，起点固定为当前位置）重排剩余节点。
   - 到骨架点：对该点仍 `unknown` 的频道逐个测量（**同时**完成检测与证书累加）；然后 `_refine_at` 顺路补测 2 个"最不确定"的已检出频道。
   - 到源节点：走预测点 → 测量 → `_try_clear` → 失败则 `pursue` 追 3 步 → 冷却。
   - 关键设计：**取消 v2 独立的 hunt 阶段**（v2 先 hunt 一轮 seed1 就烧 6499m/1375s，路径与证书巡回完全重复）。

3. **`finalize`**：对残余源做**兜底 TSP 巡回**，追踪预算逐轮放大（`5+3r` 步）。理想情况**应当为 0**（全部在巡回中清完）——目前 24 种子里只有 8 个为 0，**这是首要要消灭的成本**。

### 3.1 追踪（pursue）的三条经验规则（都是血泪换的）

| 规则 | 内容 | 理由 |
|---|---|---|
| **点亮侧优先** | 候选点评分 `dist − LIT_BONUS·cos(v, u)`，`u` = 由 MEC 中心指向已有测点的平均方向 | 定向源在盲侧**永远测不到**，必须先绕到点亮侧 |
| **黑侧惩罚** | 记 `no_signal` 的方位进 `self._blind[ch]`，`dist + BLIND_PEN·cos(v, b)` | 避免反复撞盲侧 |
| **长条端采样** | MEC 半径 R>40 时，沿主轴两镜像端 `C ± t·R·u (t=0.5,0.85,1.2,1.55)`、沿最后示向度远端 `C + t·R·e (t=0.6,1.0,1.4)` 都要采样；R>150 时**跳过各向环**（纯浪费步数） | 单/双方位近共线时 MEC 是**长条 sliver**（R~680m），源在**两端尖点**，中心周围 380m 环上根本够不着 |

> ⚠️ 试过并**失败**的两条：
> - 给 `+e` 方向**符号偏好**（"源必在 C+R·e"）⇒ 降到 20/24。**源不在 C+R·e**，长条两端都必须对称采。
> - 把"大残差长条也加进巡回节点" ⇒ 巡回变长 > finalize 省下的（620.9 vs 600.1）。已用 `SLIVER_NODE_MIN = 1e9` 关闭（设 `150.0` 可开启）。

### 4.1 ⚠️ 可行性上界：优化器的代价模型给出的「地板」

`opt_cover.py` 里的解析代价模型（按 13 个源 / 7 个空频道标定）是：

```
J(N) = [ tour(N) + 2·n_src·E_G[dist(G,S)] ] / SPEED     # 移动 (注意是 2×：往返)
     + 6 · (20 − n_src) · N                              # 空频道: 每停点 ×(5s测 + 1s换)
     + 60 · n_src                                        # 活动频道: 检出+逼近+清除
```

对现用 26 点：

```
J = (18758 + 2×13×313)/5 + 6×7×26 + 60×13
  = 5379 (移动) + 1872 (测量) = 7251 s/种子
```

**实测 7580s vs 模型地板 7251s ⇒ 只有 330s 余量。**
这意味着 §4 表格里那 2260s 并非"全是浪费"——**其中约 1600s 的绕行是模型已计入的固有代价**（源离巡回路径平均 313m，13 个源往返 ≈ 8138m ≈ 1628s）。

## 5. 通向 <500s 的路线图（按性价比排序）

### ① 用「最便宜插入」替代「源作为 TSP 节点」（**最高优先级**）
**现状问题**：一旦某个源被检出，就把它塞进节点集合，触发**整条巡回重排** ⇒ 巡回被动拉长，绕行 1800s 大半来自这里。
**改法**：不要全局重排。当源被检出的 MEC 半径 `R ≤ SRC_NODE_TOL` 时，计算把它**插入当前开放巡回的哪条边最省**：

```
extra(p) = min over edge (a,b) of  [ d(a,p) + d(p,b) − d(a,b) ]
```
若 `extra ≤ ENROUTE_MAX`（且 `extra ≤ 2·d(cur,p)`），才插入；否则不插，留给 finalize 或后续顺路。
**预期收益**：把"往返"变"单程"，绕行从 ~1800s 降到 **~900s（省 ~900s）**。
（上界论证：模型把绕行写成 `2·n_src·E[dist]` 即**往返**；源是在巡回停点上被检出的，插入到相邻边即可**顺路**到达，理论上可省掉一半。要达到 900s 需要插入决策做得很干净。）

### ② 让 finalize 恒为 0
把 ① 做扎实后，末段应无残留。若仍有，检查 `_serve_source` 里 `pursue(max_steps=3)` 的 3 步预算是否够——长条源常常 3 步走不到尖点。可考虑：**检出时长条就一次性把两个尖点都排进当次巡回**（而不是追 3 步就冷却）。

### ③ 降低测量次数（省 ~500s 空间）
- `REFINE_BUDGET = 2` ⇒ 每骨架点 2 次补测 × 26 点 = 52 次 = **260s**。可试 1 或 0，用模拟器验证收敛是否变慢。
- 对**已检出且 MEC 已收敛（R ≤ 20m，可直接清）**的频道，**不再在每个骨架点重复测**，只保留清除动作。
- 已对 `unknown` 频道做 `check_empty` 早退，但**检测本身不可避免**（每个 unknown 频道在每个骨架点都要测一次以完成证书）。

### ④ 巡回本身再榨 3~5%（省 ~150s）
`_tsp_open` 是最邻近 + 2-opt（5 passes）。26 点规模可升级为 **Or-opt / 3-opt**，或对固定骨架离线跑一次**精确 Held-Karp**（26×2²⁶ 太大，但对**固定点集**可用 Concorde/LKH 离线求优，把最优 order 硬编码——注意起点是动态的当前位置，可存"最优环 + 破环策略"）。
> 已用 `opt_cover.py` 做过环参数搜索：**当前 400/6+1300/8+1900/12 已近最优**（J≈5230s），换任何参数都更差。所以只能改 TSP 求解器，不能改几何。

**证据（`tmp/optcN2.txt`，修正 maxgap 约定后的完整扫描）：** 该优化器在 N=26 上只能找到**更短但非法**的解——
`tour=18426m`（比现用 18758m 短 332m ≈ 66s）却在密集网格上 `maxgap=196.7°` **失败**；
它列出的"VALID 名单是空的"。而现用 26 点是唯一能收敛到 `maxgap=180.000000` 的解。
⇒ **几何层面已被榨干，别再把时间花在"搜更短的骨架"上**；收益只能来自策略层的绕行与 finalize。

### ⑤ 高风险高回报：自适应双层证书（**需严谨性论证**）
证书按 R=1000（最坏）设计 ⇒ 26 点。若先用 R=1500 的**短巡回**（点数可大幅减少，估计能省 1000s+）扫一遍：
- 已检出源 ⇒ 直接进入定位清除流程；
- 未检出且未清除的频道 ⇒ **仍需 R=1000 证书才能判空**（因为空频道=全圆域无源，而源半径可能恰为 1000）。
⇒ 所以对**空频道**省不掉。但**对已检出频道省掉了它在完整 26 点上的重复测量**。
**净收益**取决于空频道数量（20 频道 − 10~16 源 = **4~10 个空频道**）。需先算清楚再决定，别贸然改。
