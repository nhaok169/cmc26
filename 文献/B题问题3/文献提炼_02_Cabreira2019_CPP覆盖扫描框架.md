## 2. 提取的关键框架

### 2.1 CPP 方法分类树（原文 §2–§4）

```
CPP
├── 无分解法（简单几何模式，适合规则区域/单机器人）   ← B题圆域适用
│   ├── 往返式 back-and-forth（平行扫掠 / creeping line）
│   ├── 方形式（从中心向外扩展的 expanding square）
│   ├── 扇形搜索 sector search（120°转角、三轮回中心、再偏移30°重复）
│   └── 螺旋式 spiral（沿区域外顶点逐层收缩到中心）
├── 精确单元分解（牛耕式 boustrophedon，Choset）——保证覆盖的经典证明
└── 近似单元分解（栅格法）
```

### 2.2 性能评价指标体系（原文 §2.3，B题论文可直接借用做指标对比表）

| 指标 | 定义 | 对 B题的映射 |
|---|---|---|
| 覆盖率 | 已覆盖面积/总面积 | 目标：检测点集合覆盖整个 1800m 圆盘（见文献提炼04 §3） |
| 路径长度 | 行驶总里程 / 5 m/s | 机器狗移动时间（5 m/s 直线） |
| **转弯数** | 转向机动次数 | 机器狗起停/转向的隐性时间代价（一阶成本项） |
| 完成时间 | 任务总时长 | 平均定位清除时间（题目统计量） |

**关键论断（原文）**：转弯次数常被作为覆盖任务的首要性能度量——每次转弯需减速-旋转-加速，转弯越多时间与能量消耗越大。**最小化转弯数 ≈ 节省任务时间**。

### 2.3 在线/离线信息可用性二分（原文 §2.4）

- **离线覆盖**（已知全部环境信息）：分解→规划→执行三段式，路径预计算
- **在线覆盖**（sensor-based，边测边规划）：B题属于此类——干扰源数量/位置未知，必须"检测→更新信念→重规划"迭代。这正是问题 3 与普通 CPP 的本质区别：**覆盖的对象不是地面而是"信号可检测域"**

### 2.4 与 B题的差异警示（本文档作者的适配分析）

| CPP 假设 | B题实际 | 后果 |
|---|---|---|
| 传感器连续扫描（移动中即覆盖） | 必须**停下**才能检测，每次 5s/频道 | "扫线"退化为"停点序列"，扫描时间是显式大头成本 |
| 单一传感器全覆盖 | 20 频道×每频道独立 5s | 全扫一点 = 119s，覆盖式扫描代价极高（见文献提炼04） |
| 覆盖即完成 | 覆盖只是发现，还需定位→接近→清除 | CPP 只是问题 3 的第一阶段子模块 |

## 3. 对问题 3 的直接启示

1. **圆域 + 无分解模式**：B题目标区域是规则凸圆域，无需单元分解，可在"平行扫掠 / 扩展方形 / 螺旋 / 扇形"中做解析比较（转弯数与路径长度都有闭式或数值可算）
2. **扫描模式解析比较表**（论文素材）：按"停点数、行驶里程、转弯数、扫描时间"四指标列表对比各模式——直接对应 Mrite 论文规范的"算法对比表"
3. **在线重规划**：检测到信号→交会定位→前往清除→继续扫描的闭环，符合 sensor-based coverage 框架；被检出频道的停点集合应从后续扫描中动态剔除（避免重复检测已定位源）
4. **转弯代价**：机器狗 5 m/s 直线行进，模式选择应使**停点链的总折线长度 + 起停次数**最小——与 Bähnemann 2021（arXiv:1907.09224，把牛耕式覆盖建成含转弯代价的 GTSP）配套使用
